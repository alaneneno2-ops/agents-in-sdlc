GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、ローカルで進行する各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューして個々の変更を採用または取り消し、会話に追加のプロンプトを送って作業を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 進行中のセッションにライト モードの切り替えを追加するよう依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライト モードも追加してほしいという要望がありました。新しい会話を始めず、進行中のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案したら、インラインの差分で次のいずれかを選択します。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッションで変更されたファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに依頼する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。会話を続けることで、エージェントは変更したコンポーネント、スタイルの方針、設定を local storage に保存する方法を引き継げます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好ましくない方法でトグル UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** で停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションを調整すると、最初からやり直すより早く済みます。追加プロンプトで「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」、方向修正で「トグルを 3 つに増やさず、既存の設定パネルにライト モードを追加する」、範囲の拡張で「両方のトグルにキーボード ショートカットも追加する」といった依頼ができます。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが編集したファイルをまとめて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. いくつかのファイルを開いて差分を確認します。カスタム エージェントが指示したアクセシビリティ パターンとして、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して調整しました。ファイル編集を確認し、変更を採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加プロンプトを使って進行中のセッションを調整しました。
